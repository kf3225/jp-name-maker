# Effect as the application core

The Worker (generation/validation pipeline, rate limiting, and the Hono handlers) is built on **Effect** rather than plain async/await TypeScript. Schemas use `Effect.Schema`; dependencies (the Workers AI binding, the KV namespace, the real-surname list) are provided via **Layer**; the LLM is called through **`effect/ai`**; and the per-person rate-limit counter is backed by Effect's **KeyValueStore** abstraction over Cloudflare KV.

This choice exists because the hardest part of this app is the validate-then-regenerate loop ([ADR-0001](./0001-llm-generation-with-validation-layer.md)): the LLM produces candidates and a validation layer must reject any that violate the real-surname constraint or invalid kanji/readings, then retry. Effect's typed error channel plus `Effect.retry`/scheduling expresses that loop directly, and Layer makes the Workers AI / KV / surname-list dependencies injectable so the heavy test suite ([ADR-0005](./0005-development-guardrails.md)) can substitute test doubles. The rejected alternative is plain `Promise`/`try-catch` TypeScript, which buries the retry/DI/validation logic in hand-rolled plumbing and is harder for both humans and the coding agent to keep correct.

**Consequences**: the Worker bundle is larger (~138 kB gzip vs ~17 kB for Hono alone), which is acceptable on the server and is deliberately kept off the client (Effect runtime is server-only; the Preact client consumes only inferred types). The team and any coding agent must work in Effect's idiom (generators, `yield*`, Layer composition), which AGENTS.md and the lint setup must reflect. This revises the schema-validation portion of [ADR-0004](./0004-frontend-and-api-stack.md) (Effect.Schema replaces valibot).
