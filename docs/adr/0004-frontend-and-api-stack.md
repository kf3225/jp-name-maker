# Frontend and API stack: Preact + daisyUI + Hono + Effect on Vite+, with pnpm

The web app is a single Cloudflare Worker (API) plus a Preact SPA client, built with one toolchain. We chose: **Preact** for the UI (not React), **daisyUI** for styling (CSS-only), **Hono** for the Worker API, **Effect** (`effect`) as the application core — including **Effect.Schema** for validation, **Vite+** as the unified build/dev/test toolchain, and **pnpm** as the package manager.

The unifying principle is a **lean client, capable server**. On the client we trade the "default heavier" option for a smaller one: Preact over React saves bytes but forces dropping **shadcn/ui** (React/Radix-only, no official Preact support); **daisyUI** replaces it as a framework-agnostic, CSS-only Tailwind plugin. On the server we accept a heavier, more capable runtime: **Effect** gives an effect system, typed errors, retry/scheduling, dependency injection (Layer), and a platform abstraction (KeyValueStore) that the generation/validation core and rate limiting need anyway. **Hono** is the canonical Workers router and exports as the Worker's default fetch handler under `@cloudflare/vite-plugin`; Effect runs inside the handlers. **Vite+** provides one unified config (dev/build/test/lint/fmt, Rolldown bundler); its 0.x maturity is accepted because a spike verified that `@cloudflare/vite-plugin` + `@preact/preset-vite` + Hono + Effect all build together under the Vite+ core alias (Worker bundle ~138 kB gzip, client unchanged at ~12 kB).

**Validation**: **Effect.Schema** is the single schema library on the server. It replaces the earlier valibot choice (revised before implementation) so there is one schema library end-to-end; the client never imports the Effect runtime and instead consumes TypeScript types inferred from the shared schemas.

See [ADR-0006](./0006-effect-as-application-core.md) for the architectural decision to build the Worker core on Effect (Layers, retry-driven validation, KeyValueStore rate limiting). **Consequences / pnpm gotcha**: because pnpm ignores npm's `package.json` `overrides`, the Vite+ alias override (`vite → npm:@voidzero-dev/vite-plus-core`) must live in `pnpm-workspace.yaml` under `overrides:`. Vite+ is still 0.x, so breaking-change risk on upgrade is an ongoing watch item.
