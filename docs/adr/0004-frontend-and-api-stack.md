# Frontend and API stack: Preact + daisyUI + Hono + valibot on Vite+, with pnpm

The web app is a single Cloudflare Worker (API) plus a Preact SPA client, built with one toolchain. We chose: **Preact** for the UI (not React), **daisyUI** for styling (CSS-only), **Hono** for the Worker API, **valibot** for schema validation (not zod), **Vite+** as the unified build/dev/test toolchain, and **pnpm** as the package manager.

The unifying principle is edge- and bundle-size-consciousness, which is why each choice trades the "default heavier" option for a smaller one. Preact over React saves client bytes but forces dropping **shadcn/ui** (which is React/Radix-only and has no official Preact support); **daisyUI** replaces it as a framework-agnostic, CSS-only Tailwind plugin. **valibot** over zod for the same size reason (tree-shakable). **Hono** is the canonical Workers routing framework and exports cleanly as the Worker's default fetch handler under `@cloudflare/vite-plugin`. **Vite+** gives a single unified config (dev/build/test/lint/fmt, Rolldown bundler); accepting its 0.x maturity is justified because a spike verified that `@cloudflare/vite-plugin` and `@preact/preset-vite` build correctly together under the Vite+ core alias.

**Consequences / pnpm gotcha**: Because pnpm ignores npm's `package.json` `overrides` field, the Vite+ alias override (`vite → npm:@voidzero-dev/vite-plus-core`) must be declared in `pnpm-workspace.yaml` under `overrides:`, not in `package.json`. Vite+ is still 0.x, so breaking-change risk on upgrade remains an ongoing watch item. The verification spike (which used npm) confirmed the build graph; the pnpm setup mirrors it via the workspace overrides.
