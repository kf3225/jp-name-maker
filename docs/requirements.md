# jp-name-maker 要件定義

さまざまな言語の名前とそのルーツから、日本風の名前の候補を生成するWebアプリ。

> ドメイン用語は [CONTEXT.md](../CONTEXT.md) を、アーキテクチャ決定は [docs/adr/](./adr/) を参照。

## 1. 目的

入力名（多言語）と、その背後にあるルーツ（意味・由来）から、音の響きと意味の2軸で日本風の氏名候補を生成し、それぞれの根拠とともに提示する。ルーツとして、システムが自動で引くエティモロジーと、ユーザーが親などから聞いた話（任意）を合成して用いる。

## 2. 入力

| 項目       | 必須/任意 | 内容                                                                                                                   |
| ---------- | --------- | ---------------------------------------------------------------------------------------------------------------------- |
| 名前       | 必須      | 変換元の氏名。MVPはラテン文字＋主言語圏（目標: 多文字体系フル対応／キリル・アラビア・ハングル・タイ・CJK・ベトナム等） |
| ルーツ話   | 任意      | ユーザーが自分の言葉で書く名前の意味・由来・家族の物語。システムの自動エティモロジーを上書き・補強する                 |
| 性別       | 任意      | 未入力時は中性寄りの名を中心に、男女をばらけて提示                                                                     |
| 雰囲気タグ | 任意      | 伝統的／現代的／かわいい／かっこいい／中性的（0〜複数選択／未選択は自動で多様に）                                      |

※エティモロジー（名前本来の意味）はシステムが自動取得する。ユーザーは名前だけ入力しても意味名が生成できる。

## 3. 出力（候補）

1回の生成で**軸構造化された複数候補（既定4〜6件）**を出す。「もっと出す」で再生成（多様性を出す）できる。

### 候補1件の構成

- **漢字氏名**（姓＋名）
- **読み**: ひらがな ＋ ローマ字 ＋ **発音記号(IPA推定)**
- **根拠**: 響き名/意味名の**軸ラベル** ＋「どの音・どのルーツから来たか」の1〜2文（姓・名それぞれ）

すべての候補に根拠が必ず付く。

### 姓の生成

3つの来源を候補に出し、いずれも実在姓に限定する。

1. **音反映**: 入力姓に音が近い実在姓（例: Smith → 須磨）
2. **意味由来**: 入力姓のルーツから（例: Smith=鍛冶屋 → 鍛冶）
3. **フォールバック**: 音・意味いずれも実在姓が成立しない場合は、無関係の実在姓

### 名の生成

- **響き名**: 入力名の発音から当てた漢字
- **意味名**: 入力名のルーツ（意味）に合う漢字

## 4. 生成方式

LLM生成 ＋ 検証レイヤー（[ADR-0001](./adr/0001-llm-generation-with-validation-layer.md)）。

- LLMが候補を生成し、後段で「実在姓リスト・漢字辞書・読み妥当性」を検証・再生成する。
- 実在姓制約（捏ねた珍姓を出さない）と、自由テキストのルーツからの創造的意味名生成を両立する。
- 生成は非決定的（「もっと出す」の多様性の源）。

## 5. 提供形態・アーキテクチャ

- **Webアプリ**（ブラウザ・公開）を主軸。生成コアはAPI化可能な形で分離実装する。
- **Cloudflare** にホスト（[ADR-0002](./adr/0002-deploy-on-cloudflare.md)）: Workers（アプリ＋生成コア）／Turnstile（ボット対策）／Workers AI（LLM生成）。
- **インフラは完全にTerraform管理**（[ADR-0003](./adr/0003-infrastructure-fully-managed-by-terraform.md)）: Workers・Turnstile・KV・バインディング・シークレット等すべてをTerraformで provisioning し、コンソール手作業を禁止する。アプリコードのデプロイはWrangler、リソース/バインディングはTerraformが所有。
- **技術スタック**（[ADR-0004](./adr/0004-frontend-and-api-stack.md)／[ADR-0006](./adr/0006-effect-as-application-core.md)）: フロントエンド=Preact＋daisyUI(CSS-only)。API/Worker=Hono。**アプリケーションコア=Effect**（Schema/Layer/`effect/ai`/KeyValueStore、[ADR-0006]）。ツールチェイン=Vite+（`@cloudflare/vite-plugin` との互換はスパイク検証済）。パッケージマネージャ=pnpm。スキーマは Effect.Schema に一本化（クライアントは型のみ共有・Effectランタイム非搭載）。

## 6. ユーザーデータ・永続化・シェア

- **アカウント無し**。サーバーにユーザーデータを保持しない。
- **お気に入り・履歴**: ブラウザ(localStorage)に保存。
- **シェア**: 生成結果ごとに共有リンク／カード画像を生成。
- ルーツ話（個人的な家族情報）は生成時に使い捨て、サーバーに蓄積・保持しない。

## 7. コスト・アクセス制御

- **無料**。LLM APIキーはサーバーが保持（ユーザーに持たせない）。
- **再生成レート制限**: **1人1日あたり10回**。初回生成も再生成（「もっと出す」）も同じ1つのクォータを消費する。
- **Turnstile** でボットを弾く。
- ※アカウント無し（§6）のため「1人」の識別はベストエフォート: **クライアント側の匿名ID(localStorage)を主キーとし、IPを補助/異常時フォールバックに用いる**。カウンタはサーバー側(Cloudflare KV等)に `rl:{anonymousId}:{date}` で保持し日次TTLで消す。完全性は求めず「フリー層の乱用防止」として割り切る。

## 8. スコープ

### MVP（第一目標）

- 入力: ラテン文字＋主言語圏の氏名
- 出力: 軸構造化4〜6件＋「もっと出す」
- 姓: 音反映＋意味由来＋実在姓フォールバック
- 生成: LLM(Workers AI)＋検証レイヤー
- 永続化: localStorage／シェア: リンク・カード
- アクセス: 無料＋レート制限＋Turnstile

### 目標（段階拡張）

- 入力の多文字体系フル対応（キリル・アラビア・ハングル・タイ・CJK・ベトナム等）
- 発音（音声）入力による響き名精度向上
- 候補anatomyの拡張（各漢字の意味・画数、音の近さスコア等）
- （必要なら）エティモロジーを辞書優先＋LLM補完に切り替え

## 9. 非機能（指針）

- **プライバシー**: ルーツ話をサーバーに蓄積しない（使い捨て）。
- **コスト**: 1生成あたりの候補数・プロンプトサイズを上限（既定4〜6件）に抑え、Workersの実行制限・Workers AIコストに収める。
- **品質**: 実在姓制約・漢字/読みの妥当性を検証レイヤーで機械的に担保する。
